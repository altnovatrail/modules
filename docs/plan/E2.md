#### T10. Сравнение с опубликованными версиями в CI

- **Цель:** CI сравнивает каждый модуль с опубликованными версиями по разделу 3.2 [docs/architecture.md](../architecture.md):
  - индекс новейшего релиза `modules` — после `release-verify`;
  - пакеты всех опубликованных версий модуля, снятые тоже, и через переход формата — по записям индекса;
  - вызов `module-kit diff --index … --published …`, а до первого релиза — `--first` (поправки 2026-11-02 и 2026-11-06 к R03).
- **Сделать:**
  - рецепт:
    - находит новейший релиз без токена;
    - проверяет его `module-index.json` рецептом `release-verify`;
    - скачивает архив каждой версии модуля по публичному адресу из записи (раздел 3.3 там же);
    - отдаёт `diff` пакеты файлами без `device/`.

    Распаковка берёт из архива только `inventory.json`, `server.json` и `device.json`, а ссылки и пути вне папки отвергает: цепочку дайджестов сверяет `diff`;
  - нет релиза — `--first`. Это решает рецепт, явно: молча пропущенный индекс не проходит;
  - код завершения `diff` — код job. Отчёт `diff` — в лог;
  - тесты: индекс и пакеты-образцы, без сети — та же версия с тем же дайджестом, та же версия с другим дайджестом, новая версия, нет пакета версии из индекса, `--first`. Подпись в тестах не проверяется: её держит `release-verify`, и тест называет это.
- **Не делать:** гейт `sim` — Д5; eval-раннер — E4.
- **Как проверить:**
  - тесты зелёные;
  - `just -f spec/justfile docs-check-repo` зелёный;
  - обязательные проверки pull request зелёные;
